# Kritische Reflexion zur gesamten Aufgabenstellung

Grundsätzlich halte ich es für sehr wichtig, sich im Studium mit dem Thema Vibe Coding auseinanderzusetzen. Ich finde es positiv, dass dieses Modul aktuelle Entwicklungen im Bereich KI-gestützter Softwareentwicklung aufgreift. Nach meiner bisherigen Erfahrung ist es eines der wenigen Module, in denen diese Entwicklung überhaupt praktisch thematisiert wird.

Auch inhaltlich fand ich die Aufgabenstellung spannend und hatte viel Spaß bei der Bearbeitung.

Grundsätzlich sehe ich an diesem Punkt jedoch ein Problem. Das ITS-Studium ist berufsbegleitend aufgebaut. Einige Studierende verfügen bereits über sehr gute Programmierkenntnisse, andere jedoch nicht. Das Studium selbst qualifiziert aus meiner Sicht nur sehr begrenzt für komplexere Programmieraufgaben. Ich kann beispielsweise einfache HTML-Formulare oder grundlegende JavaScript-Funktionen erstellen, stoße bei größeren Anwendungen aber schnell an Grenzen.

Hinzu kommt, dass in einem berufsbegleitenden Studium Wissen teilweise über längere Zeiträume hinweg nicht aktiv angewendet wird und dadurch wieder verloren gehen kann. Anders als in einem klassischen Vollzeitstudium bleibt neben Beruf, Studium und anderen Verpflichtungen oft wenig Zeit, sich zusätzlich aus Interesse intensiv mit Programmierung auseinanderzusetzen.

Daher wirkt die Aufgabenstellung auf mich nur bedingt fair, wenn bewertet wird, wie komplex das entstandene Projekt ist oder wie gut man den von der KI erzeugten Code im Detail beurteilen kann. Studierende mit bereits vorhandenen Programmierkenntnissen sind hier deutlich im Vorteil. Eigentlich sollte aus meiner Sicht stärker im Mittelpunkt stehen, ob verstanden wurde, wie Vibe Coding sinnvoll eingesetzt wird: also wie man KI-Werkzeuge steuert, Ergebnisse überprüft, iterativ verbessert und den entstandenen Code zumindest auf konzeptioneller Ebene erklären kann.

Diese Kritik habe ich bereits an die Studiengangsleitung weitergegeben. Ich halte es aber auch für wichtig, sie als Feedback direkt an den Dozenten weiterzugeben.

Ein ähnlicher Punkt betrifft auch das Praxisprojekt. Gerade im Bereich IT-Sicherheit gibt es viele relevante Aufgabenfelder, die nicht ausschließlich aus Programmierung bestehen. Eine zu starke Fokussierung auf reine Programmierung kann deshalb aus meiner Sicht dazu führen, dass andere wichtige Kompetenzen des Studiengangs weniger sichtbar werden. Und wie gesagt, benachteiligt eben auch Studierende.

Zusätzlich zeigt sich aus meiner Sicht an der Aufgabenstellung zu Aufgabe C selbst, dass das erwartete Niveau möglicherweise zu hoch beziehungsweise nicht eindeutig genug formuliert war. Gerade der Begriff „distributed app“ wurde offenbar von vielen Studierenden nicht in dem Sinne verstanden, wie von Ihnen gemeint war.
Dass diese Unklarheit nicht nur bei einzelnen Personen aufgetreten ist, spricht aus meiner Sicht dafür, dass die Aufgabe für den vorhandenen Wissensstand vieler Studierender zu anspruchsvoll oder zumindest zu offen formuliert war. Gerade in einem berufsbegleitenden Studiengang mit sehr unterschiedlichen Programmierkenntnissen wäre eine genauere Eingrenzung oder ein einfaches Beispiel für eine tatsächlich verteilte Anwendung hilfreich gewesen.
